Market research

Do other vendors couple live data and simulation?

Yes, widely, and often more mature than in OpenTSx. The combination OpenTSx pursues appears in none of the sources checked.

Grid tools estimate the state online at the control system, process twins run on live data, and on 2026-10-08 Siemens announced a physics-based twin with real-time optimization for a 100 MW electrolysis plant. ETAP comes closest to the three operating modes of OpenTSx, but is limited to electrical grids. That is why our message is not "We couple live data and simulation" but the combination.

Positioning

Where OpenTSx differs

  1. One set of building blocks, three operating modes.The same atoms run as shadow, as what-if and as forecast; the operating policy (schedule, human, optimizer) is exchangeable.
  2. Provenance per value down to every KPI.Five classes from measured to synthetic, passed on through the whole model chain.
  3. Bit-identical replay on an open log.The run id is derived from the wiring plan, the inputs, the interventions and the code version. Disputes and audits can be recomputed.
  4. Federable, with a measured design rule.Feedback loops belong in one processor, loose coupling is enough in between; the result stays bit-identical.
  5. Evaluation principle as a product rule.Coordination potential = coordinated alternative minus reference operation, with the same information. Modeled is not proven.
  6. Start open and small.Apache 2.0, Kafka protocol, Iceberg, OpenMetadata. Stage A needs no simulation.

Not a unique selling point

  • Coupling live data and simulation
  • What-if scenarios and forecasts
  • State estimation and calibration
  • "Open" alone

Where vendors are stronger

  • Maturity and installed base
  • Depth of physics in the models
  • Security attestations and control system integration
  • Support, ecosystem, user interface

Conclusion: complement, do not replace. Grid twins, APM systems and electrolyzer suites deliver inputs to the cluster twin.

Sample post for week 1

The first post

The valve closes.

01:00. The hydrogen offtaker closes its valve. Nothing dramatic, really.

But the pipeline keeps filling up, and the pressure rises. The twin reports: less than one hour of buffer. At 40 bar the electrolyzer curtails to protect itself. Its schedule is violated, and the direct marketer suddenly has to place about 5 MW more power.

Four parties, four systems, one chain. Nobody did anything wrong, and it still costs money.

With OpenTSx we play this chain through before it happens:
→ What-if: the valve opens again at 02:00, and the shutdown does not happen.
→ Forecast from 01:10 with a pressure-aware policy: no shutdown, no overpressure, but an earlier deviation from the schedule instead.
→ Every number shows whether it is measured, reported, forecast, estimated or synthetic.

To be honest: this runs on synthetic data today. The code is open (Apache 2.0), and the case can be recomputed with one command.

Do you operate a cluster of wind, electrolysis, storage or direct supply and want to know what separate operation costs? We start with a potential report from your existing data, entirely without simulation.
