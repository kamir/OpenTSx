# Appendix A: Command-line tools

Build once (`mvn -q install -DskipTests`), then run `bin/opentsx <command> [options]`. The launcher computes the
runtime classpath of a module with Maven (`dependency:build-classpath -DincludeScope=runtime`), caches it in
`<module>/target/classpath-runtime.txt` and adds `conf/`. When the classpath holds slf4j-api but no slf4j-simple, it
also adds the slf4j-simple of the same version, so log lines on stderr follow `conf/simplelogger.properties`.
For `stats-flink` the launcher also caches the provided scope in `opentsx-flink-core/target/classpath-provided.txt`,
adds neither `conf/` nor slf4j-simple and logs through log4j2 with `conf/log4j2-stats-flink.properties`.
`bin/opentsx --help` lists the commands.

The container image `opentsx-tools` is published as `ghcr.io/kamir/opentsx-tools:<version>`
([chapter 12](12-operations.md#124-run-the-tests)). The k3s manifests of the [DevOps guide](../devops/README.md) name
it `opentsx/tools`. It runs `opentsx <command>` with these commands of `bin/opentsx`: `windpark-sim`, `stats`,
`metadata`, `retrieval-server`, `vectors`, `twin`, `house`, `boat`, `dwd`, `modbus`, `twin-live`, `market` and
`classpath`. It has no `stats-flink`, `twin-coupling` or
`twin-schemas`. Its `twin`, `house` and `boat` do not switch to the history twins on `--history`; run
`history-twin twin|house|boat ...` instead. The image adds `studio-export <out.json>` (Smart Topics Studio data) and
`kafscale-check --kafscale <bootstrap> [--domain d] [--provision true --partitions n] [--timeout PT20S]`
(reachability of the bootstrap and the advertised broker addresses, topic provisioning, record counts per topic).
`config` and `version` run only through `bin/opentsx`.

Other scripts in `bin/`:

* `000_validate_environment.sh`: environment check.
* `010_build.sh`: build.
* `000_launch_tsa_workbench.sh`: the 2.x GUI.
* `005_minimal_no_kafka_demo.sh`: the 2.x sine-wave generator (`org.opentsx.lg.TSDataSineWaveGenerator`) without
  Kafka; it writes CSV files to `data/temp/`.
* `120_run_demo.sh`: the 2.x GUI `org.opentsx.app.bucketanalyser.MacroRecorder2` through `mvn exec:java`.
* `episode_*.sh`: 2.x guided demos.
* `run_all_tests.sh [--quick|--full|--validation-only|--demo-only]`: `--quick` and `--validation-only` run
  `ExerciseValidationTest` of `opentsx-core`; `--demo-only` checks the syntax of the `episode_*.sh` scripts; `--full`
  (the default) does both and checks that five documentation files exist. It writes `test-report.txt` and
  `test-summary.json` to the repository root.
* `build_docs_pdfs.sh`: PDF of this manual, via `mvn -Ppdf-manual`.
